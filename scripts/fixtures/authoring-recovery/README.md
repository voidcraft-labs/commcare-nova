# Frozen authoring recovery acceptance

These synthetic requests contain no incident documents or private user material.
The source bytes and answer are frozen before any paid run. `frozen.json` records
their SHA-256 digests. Keep the first result, including failures, in the private
trial directory. Do not change a request, coach the agent, repair its app, or add
feedback after observing an outcome.

Copy `ledger-template.json` once into the private campaign directory and pass that
same ledger to every initial or resumed trial. Its $25 aggregate ceiling includes
architect, peer, translation and document extraction calls. The existing ledger
reserves each actual provider request before dispatch, retains unresolved calls at
their full reservation, and refuses dispatch when the remaining campaign balance
cannot cover it. A budget refusal is a retained outcome, not permission to reset
the ledger. Use production model roles and production review limits.
Pass `--trial-config scripts/fixtures/authoring-recovery/trial-config.json` to
pin those roles and the production request's 60-minute outer deadline. The
orchestrator retains its production architect and peer step limits.

Run the library request with both repeatable `--library-document` arguments and
without `--document`. Library fixtures are uploaded unprepared, so success requires
the production discovery, selection and extraction path. The fixture metadata is
not added to the user's message. Retain `library-assets.json`, exact provider
requests and responses, source selections, plan, transcript, app and usage.

Run the orchard request separately. It must pause for the requested question.
Resume once with `resume-answers.json` as the ordinary answer, preserving the
original task, code, Project, conversation and ledger. If the question is not the
frozen question or the app fails, retain that result rather than inventing answers.

`evaluate-architect.ts` exercises production authoring and folds its SDK chunks;
it does not exercise HTTP admission or reconnect. Those contracts require the
separate real-route controlled-provider integration tests. Browser smoke verifies
the question interaction and continuation request identity without paid calls.

Inspect the saved apps by running these worker journeys before assessing quality:

- Register two tools; lend one; verify its borrower and due date and the two lists.
  Refuse a due date before the loan date. Return it in good condition, lend it to a
  different borrower, then return it needing repair and complete its repair.
- Register an orchard; submit a good-health visit without a follow-up date. Submit
  severe damage, observe required notes and follow-up date, refuse a date before
  the visit, and verify the orchard remains selectable with updated visit details.

Report source coverage, first delivery, each saved-app journey, all pauses or
failures, actual provider-call count and total ledger charge independently. No
claim of HTTP/reconnect or device behavior follows from a completed paid trial.
