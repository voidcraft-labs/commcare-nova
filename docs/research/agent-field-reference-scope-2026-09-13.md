# Field names and the garden construction trial

The shared authoring boundary now accepts a nested field's unique short name in
expressions, wording, edit targets and insertion anchors. Identity and exact path
take precedence. Two different fields with the same short name still require a
path or ID; aliases for one renamed field remain one candidate. Qualified paths
never fall back to an unrelated field with the same last segment.

This removes a demonstrated burden: knowing which answer to use should not
require reconstructing its container path when the answer is unambiguous. The
stored reference is still the canonical UUID. No alias is persisted and no
cross-form, repeat, type or commit rule changes. The same boundary serves the SA,
slice executor and MCP.

## Validation and next evidence

The shared-tool journey creates grouped questions with same-call wording and
conditions, inserts by a short anchor, renames a question without losing its
references, and rejects an ambiguous edit before changing the document. Another
journey resolves a nested choice in a form's typed close condition. Parser checks
cover query expressions, XPath, rename aliases, qualified misses and root-path
precedence. These establish authoring behavior, not completion quality.

Completion still needs exact accepted-input bindings and proof of the resulting
writes, effects, navigation and readback. The next construction trial should have
enough request allowance for all planned workflows, within the same financial
guards, then exercise real submissions and saved history. A larger request
allowance alone does not resolve the remaining interface or quality work.
