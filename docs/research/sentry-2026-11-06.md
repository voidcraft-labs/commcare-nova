## Evidence boundaries

- Database tests establish SQL values, transaction rollback, batching and index cardinality. Real SDK/local HTTP tests establish provider classification without live model calls.
- Private form metadata extraction needs the complete native proof CI gate to confirm upstream readers retain emitted behavior.
- The browser issue's replay is unavailable; pseudo-URL frames alone do not prove a browser extension caused it.
- Sentry span aggregate counts are extrapolated; they are not exact executed-query counts. Filtered SQL remains filtered. Named operation spans improve attribution without adding parameters or raw query text.
- Sentry event IDs in Cloud Logging provide an exact correlation key; SDK event creation does not guarantee remote ingestion.
- The index scan proves owned definitions before any concurrent drop. Production retirement, migration, traffic restoration and recurrence checks remain separately approved release work.


## Additional OAuth discovery failure found during release preparation

A fresh native Codex MCP login refused Nova before authorization: protected-resource
metadata advertised `https://commcare.app`, while authorization-server metadata
returned issuer `https://commcare.app/api/auth`. The canonical RFC 8414 inserted
OAuth and OIDC metadata paths also returned 404. Existing Claude OAuth refresh
and authenticated MCP calls still worked, so an existing token was insufficient
proof that a new client could connect. This is a newly reproduced discovery
defect, not a proven explanation for every open OAuth or JWKS Sentry event.

The additional stack fix advertises the existing canonical issuer and mounts the
missing Next routes, retaining aliases and all token verification. A real strict
MCP client exercises native provider metadata and routes through the proxy policy;
an origin-only negative control must still fail. Production verification must
also request the served canonical routes and perform fresh strict discovery.
The maintenance runbook now uses the existing OAuth credential and an exact
anonymous JWKS GET exception after index retirement; it does not require a new
API key. Browser-specific verification remains distinct from MCP authoring and
record-runtime proof.
