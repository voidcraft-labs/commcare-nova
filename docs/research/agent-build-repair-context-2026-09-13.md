The fifth trial established a separate repair failure: the helper advised
editing a catalog rule without seeing the rule or having an operation that could
edit it. PR #607 provides that operation. This change grounds both explicit
blocker reports and automatic repeated-failure help in the current private
candidate. The model receives readable fields, catalog rules, module and list
configuration, explicit case operations, and the domain's derived field-action
inventory. Stable object identities distinguish equal-name forms. Unreadable
sections are identified instead of silently disappearing.

The accepted workflow brief already contains its relevant meaning, dependencies
and constraints. The helper therefore no longer receives another complete
contract and plan. Its operation reference derives from the exact slice
allowlist and shared descriptions. It gives repair guidance against those
capabilities; it has no mutation or reset authority itself.

Controlled-provider tests prove request composition and strict decision parsing.
Real Postgres journeys prove both helper triggers observe the invalid catalog
rule in the current private revision before repair and canonical publication.
Projection checks distinguish catalog and form rules, saved and form-only
answers, equal-name form identities, and unreadable relationships. These checks
establish grounding and protocol behavior, not model judgment or end-to-end app
quality. This reader starts Unit F's implementation evidence; canonical
