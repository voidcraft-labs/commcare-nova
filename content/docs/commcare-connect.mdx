CommCare Connect pays frontline workers for training and for work delivered
through an opportunity. In **App settings → Connect**, you can turn on learning,
delivery or both. Connect runs on Android. If your app runs only in Web Apps,
choose **Android only** under **Where workers use this app** to check its forms
and media first. You can choose a role before adding its first activity.

In a form, **Connect activity** lets you place a learning module, assessment,
delivery or assigned task beside the questions it belongs with. An activity
does its work when the worker submits the form. The worker can answer a
question to determine whether the activity applies. For example, a visit
can record a delivery only when the worker says they reached the household.

- A **learning module** has a name, a description and estimated hours. Zero is a valid estimate.
- An **assessment** takes its score from a form calculation. The submitted score must be a whole number.
- A **delivery** has a name and can take its person or place ID, person or place name and work area ID from the form.
- An **assigned task** identifies the task Connect should look up for the worker. Connect completes a matching open assignment once.

After submitting in Preview, **View activities** shows the names, scores,
delivery details and repeat rows the form submitted. CommCare Connect applies
the opportunity's assignments, verification rules and payment settings when
it receives a published form.

Once the Connect version is installed on Android, every form a worker submits
includes the device's location if CommCare has location permission and the
device gets a GPS fix. This applies to forms outside the learn or deliver setup too.
When a delivery form reaches CommCare Connect, its visit records that location.
If the opportunity checks for missing GPS, a visit with a location passes that check.

## Where workers open a Connect app

Connect workers open a Connect app in the Connect app on Android, signed in with
PersonalID. CommCare HQ gives them no password, so they can't sign in to Web
Apps. A Connect app therefore runs on Android only, and Nova sets that when you
turn on Connect. Turning Connect off keeps the setting; you can change it in App
settings. [Where workers use your app](./where-workers-use-your-app.mdx) lists
what else that choice decides.

### Turning off automatic location capture

After Connect is turned off, **App settings → Request location for every form**
controls the app. With that switch off, each form uses its own **Request location
for this form** switch. Publish the app, then build and release its new version
in CommCare HQ. Workers use the new settings when they install that version.

## Activities in a repeated or conditional part of a form

A form can record distinct learning modules together. Each module can occur
once in a submission, and one assessment can supply a score. A group or row
that the worker never reaches contributes no activity. If Connect reserves
the ID of a group, section or repeat containing an activity, Nova points out
where you can rename it.

Each delivery of the same unit needs a distinct person or place ID in the
submission. In a repeat where the worker adds each row, **Delivery with a person or place ID**
adds a required question and links it to the delivery. Each ID can hold up to
255 characters. If the worker enters the same ID twice, the form asks for a
different ID before they can finish. You can rename the question and its link
follows. For a brought-in form that calculates the same delivery ID for two
rows, give the worker a distinct ID to enter for each person or place or record the
deliveries in separate submissions.

Two empty IDs also count as the same ID.

A delivery can use the work area's case ID to record a visit there. If a worker
needs to mark an area inaccessible, they can send the request through the
opportunity's work-area process. When a form includes this request, CommCare HQ
keeps the photo but sends Connect only its filename. Connect declines the whole
submission, including any deliveries or learning activities in it.

Connect processes deliveries before assigned tasks in the same submission.
A worker can complete the task in its own form before submitting the delivery,
or the form can offer mutually exclusive paths resulting in just one of them.

## Activities and pages

A Connect activity can sit before, between or after the pages of a form.
It keeps its position in the submission without giving the worker an extra screen.
To make an activity depend on a group or repeat, place it inside that group or repeat.

## Names and descriptions

CommCare Connect reads each learn module's, deliver unit's and task's name and
description from the form exactly as you wrote them. One phrase can't go in
them: instance( followed by a quoted name and a closing bracket, such as
instance('casedb'). CommCare HQ reads that as a data source wherever it appears
in a form, and would add the source to the form or stop the app's build. A space
before the bracket keeps it as text.

## IDs

Each activity has a question ID at its place in the form. That ID also names
the activity in the submitted form. IDs start with a letter and can use
letters, digits, underscores and hyphens. Learning module and task IDs have
room for 50 characters. Delivery unit IDs have room for 100.

CommCare Connect keeps its records under these IDs, so it helps to settle them
before you publish. If you change a deliver unit's ID after that, Connect turns
away each delivery of the new ID until an opportunity manager adds it to a
payment unit, and CommCare HQ doesn't send those deliveries again. Connect reads
a changed learn module ID as a second module, and a task already assigned under
an old ID is never completed by the form.

## Publishing a Connect app

A Connect app's forms reach CommCare Connect only through CommCare HQ: the
project space forwards each form to Connect once a worker submits it. That
needs two things on the project space, and no API key can read either, so the
Publish dialog asks you to confirm both:

- **Data Forwarding**, a feature of the Pro, Advanced and Enterprise plans.
  Without it, CommCare HQ takes the app's forms and sends none of them to
  Connect, so no learning or delivery is recorded there.
- **A Connect forwarder.** A project space admin adds it on CommCare HQ's Data
  Forwarding page, choosing **Forward Form Metadata to Commcare Connect** with
  the connection CommCare Connect gives them.

Nova keeps your answers with that project space until you withdraw them in
**App setup → Publishing**. The CommCare HQ app file's guide names the same two
things. See [Publishing to CommCare HQ](/docs/publishing#what-the-project-spaces-plan-includes).
