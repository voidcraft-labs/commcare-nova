title: API keys
description: Connect a tool to Nova without going through a browser sign-in.
---

API keys are the alternative to signing into Nova through your browser. Mint one in settings, paste it into your tool's config, and it stays connected.

## When to use one

Use OAuth (the default) for the everyday case: a person, a browser, one tool at a time. You sign in once and the tool stays connected until you revoke it.

Pick an API key when you want any of these:

- An unattended pipeline that runs while you're not at the computer.
- Multiple parallel tools or agents using the same Nova account at the same time.
- A shared bot account that several scripts speak through.

OAuth's sign-in needs a person at a browser, and parallel tools sharing one OAuth sign-in fight each other every time their connection refreshes. API keys don't have either problem.

## Mint a key

<Steps>
<Step>Open [Settings → API keys](https://commcare.app/settings) on commcare.app, signed in as the account that should own the key.</Step>
<Step>Click **+ New key** and pick a name. The name only shows up in your keys list, it doesn't affect what the key can do.</Step>
<Step>Pick the scopes. **Read** and **Write** are required. Add the **HQ** scopes if your tool needs to upload finished apps to CommCare HQ, and the **Projects** scopes if it manages shared Projects, members, and invitations.</Step>
<Step>Pick an expiry. **1 year** is the default. Pick shorter if you want tighter rotation, or **Never expires** for credentials you'll rotate manually on your own schedule.</Step>
<Step>Click **Mint key**. The next screen shows the full key once, copy it now. Nova hashes it after that, so if you lose the full value you'll have to mint a new one.</Step>
</Steps>

## Use it with Claude Code

Set `NOVA_API_KEY` to your key value in the environment that starts Claude Code:

```bash
export NOVA_API_KEY="sk-nova-v1-YOUR_KEY_HERE"
```

Replace the example value with your actual key. Then add a personal server configuration once:

```bash
claude mcp add-json --scope user nova '{"type":"http","url":"https://mcp.commcare.app/mcp","headers":{"Authorization":"Bearer ${NOVA_API_KEY}"}}'
```

The single quotes preserve the environment-variable reference, so the saved configuration contains no key value. Claude Code reads the key from the environment at startup. Keep it set for each unattended run.

This works with or without the [Nova plugin](../claude-code/index.mdx). With the plugin installed, Claude Code uses your personal connection in place of the bundled connection to the same endpoint. The plugin's skills and autonomous agent support both connections.

<Callout type="info">
The plugin's bundled connection uses browser sign-in. Setting `NOVA_API_KEY` alone does not change it: Claude Code removes credential environment variables from plugin-provided header helpers. The personal configuration above uses Claude Code's supported [environment expansion](https://code.claude.com/docs/en/mcp#environment-variable-expansion-in-mcpjson) and [server precedence](https://code.claude.com/docs/en/mcp#scope-hierarchy-and-precedence).
</Callout>

To return to browser sign-in with the plugin, remove your personal connection and restart Claude Code:

```bash
claude mcp remove --scope user nova
```

Without the plugin, replace the personal connection with one that has no `Authorization` header:

```bash
claude mcp remove --scope user nova
claude mcp add --scope user --transport http nova https://mcp.commcare.app/mcp
```

Unsetting the key alone leaves the API-key connection configured. A missing or rejected key fails authentication rather than falling back to browser sign-in. Check that `NOVA_API_KEY` is set in the environment that starts Claude Code, then reconnect through `/mcp`.

## Scopes

Each key can have any combination of these:

| Scope | What it grants |
|---|---|
| `nova.read` | List, read, and search apps in your account. **Required.** |
| `nova.write` | Create and edit apps. **Required.** |
| `nova.hq.read` | Look up which CommCare HQ project spaces your stored API key can reach. |
| `nova.hq.write` | Upload finished apps to CommCare HQ. |
| `nova.projects.read` | See a shared Project's member list and pending invitations, including members' names and emails. |
| `nova.projects.write` | Create shared Projects, invite members, change member roles, and move apps between Projects. |

Set scopes when you mint, change them later from the kebab menu → **Edit scopes**. Read and write are the floor; nothing in Nova works without them. The other pairs are independent opt-ins: write doesn't include read, so give a key that manages members both Projects scopes — `update_member_role` addresses members by ids that only `list_members` (a Projects-read tool) returns. Listing the Projects you belong to needs no extra scope; every key can call `list_projects`.

## Rotating and revoking

Every key in the list shows when it was last used and when it expires. To rotate, mint a new key, point your tool at the new value, then revoke the old one, there's no in-place rotation, because Nova only keeps the hash.

To revoke, click the kebab on the row → **Revoke** → confirm. The next call from that key fails immediately.

API keys and OAuth sign-ins are independent. Minting a key doesn't disturb any browser sign-ins on the same account, and revoking either kind doesn't touch the other.
